# Расширенный промпт для ручных стадий (не обычный запуск)

Работай полностью локально. Ничего не отправляй во внешние сервисы, не используй
облачные API для перевода — только локальный сервер модели.

Конвейер перевода лежит отдельной папкой — ниже она зовётся `$ROOT` (скилл
translate-en-ru-pdf-latex).
Сначала прочитай там `SKILL.md` — это регламент по каждой стадии. Скрипты и ассеты
конвейера **не редактируй** — правь только файлы текущего проекта.
Затем прочитай `docs/INTEGRITY.md`: идентичность входов/кэша, профили приёмки
и выпуск через отдельного кандидата обязательны. Не утверждай «потерь нет»
по коду процесса или числу блоков. Старый непроверяемый кэш не удаляй;
предупреди о cache miss и возможном повторном MT до массового запуска.

## Шаг 0. Окружение

- Инструменты извлечения живут в venv конвейера:
  ```powershell
  $ROOT = "D:\Конвейер"          # ← куда распакован пакет конвейера
  $env:PATH = "$ROOT\venv\Scripts;$env:PATH"
  $PY = "$ROOT\venv\Scripts\python.exe"
  ```
- Если предстоит стадия перевода — проверь, что `http://localhost:1234/v1/models`
  отвечает. Сервер молчит → **остановись** и попроси меня запустить LM Studio
  (Developer → Start Server). Модель грузить заранее не нужно — LM Studio
  подхватит её JIT при первом запросе. Если осталась только вёрстка/сборка,
  сервер не нужен вовсе.

## Шаг 1. Разведка папки

1. Прочитай заметки проекта, если есть: `PROGRESS.md`, `README*`, `NOTES*`, `TODO*`.
   Их указания (диапазоны страниц, смещение нумерации, договорённости по стилю,
   что не переводить) **приоритетнее** общих правил ниже.
2. Составь инвентарь:
   - исходники книг: pdf / epub / fb2 / docx / html / txt / md;
   - глоссарий: `glossary.tsv` (+ генератор `tsv2md.py`?) и/или `glossary.md`;
   - собственный LaTeX-каркас: `main.tex`, преамбула, `chapters/*.tex`
     с маркерами вставки вида «>>> сюда вставить … <<<»;
   - рабочие папки конвейера: `_translated\`, `*_ru\` (внутри `extract/`, `work/`, `build/`);
   - промежуточные md: извлечённый, `.clean.md`, `.masked.md`, `.ru.masked.md`, `.ru.md`.

## Шаг 1.5. Развилка по письму источника

Источник — немецкий скан XIX века готическим шрифтом (фрактура)? Тогда весь
дальнейший текст этого промпта НЕ применяется: MinerU/Marker на фрактуре дают
мусор. Маршрут — `$ROOT\README.md`, раздел «Готические тома
(фрактура)»: ocr_fraktur (deu_latf) → build_ocr_md (+structure.json) →
slim_glossary → run_doc_translate → assemble_ru_book. Короткая вставка для
запуска — `ПРОМПТ_ПАСТА.md`, блок Б.

## Шаг 2. Главная развилка — кто верстает

- **Есть свой LaTeX-каркас** (main.tex + заглушки глав) → **режим Б**: конвейер
  используется по частям, вёрстка остаётся родной. Оркестратор `translate_book.py`,
  `to_latex.sh` и `build.sh` конвейера в этом режиме **не запускать** — они построят
  параллельную книгу со своей преамбулой и проигнорируют каркас.
- **Каркаса нет** → **режим А**: всё делает оркестратор конвейера. Стадии вручную
  не гонять — повторный запуск той же команды сам продолжает с места остановки
  (извлечение пропустится, переведённые абзацы возьмутся из кэша).

## Глоссарий (до старта, в обоих режимах)

- Есть `glossary.tsv` + генератор → **источник истины — TSV**: правки только там,
  md регенерировать генератором, руками не трогать.
- Есть готовый `glossary.md` → передавать `--glossary`, флаг `--auto-glossary` не нужен.
- Глоссарий длиннее ~100 строк → сделай slim-фид для модели:
  `& $PY $ROOT\scripts\slim_glossary.py <мастер> --chapter <N> --out slim.md`
  (имена + термины-ловушки + строки главы); полный оставь для аудита после перевода.
- Глоссария нет → `--auto-glossary`.
- **Во время прогона глоссарий заморожен**: правка сбрасывает кэш перевода.

## Режим А — оркестратор

### Если ты агент, а не человек

Рецепт «запусти в фон и приходи проверять» держится не во всякой среде: на
одном сеансе отсоединённый `Start-Process` пережил границу вызова и доработал
сам, на другом погиб вместе с концом вызова, унеся часы. Поэтому:

* **проверь фон минутным опытом**, прежде чем ставить на него длинную стадию:
  скрипт, дописывающий тик в файл раз в 3 с, — и посмотреть в следующем
  вызове, растёт ли файл;
* **держись потолка одного вызова** (~50 минут): извлечение чанками ≤50
  страниц, перевод частями ≤300 блоков — обе стадии укладываются с запасом;
* **всё равно рассчитывай на возобновление**: повтор той же команды
  продолжает с кэша, и гибель процесса стоит минут, а не прогона.

Подробности и остальные ловушки агентской эксплуатации — `АГЕНТ.md`, раздел
«Работа из агентской сессии».


1. Выбери режим извлечения для PDF, заглянув в книги: плотные формулы → `math`,
   скан без текстового слоя → `scan`, иначе `auto`. Если в папке уже лежит только
   markdown — это тоже валидный вход (извлечение пропустится).
2. Запусти (часы работы; лог — обязательно в файл, а про фон см. врезку «Если ты агент, а не человек» ниже):
   ```powershell
   # одна книга
   & $PY $ROOT\scripts\translate_book.py <книга> --extract <режим> --glossary <файл>
   # все книги папки
   & $PY $ROOT\scripts\translate_folder.py . --extract <режим> --glossary <файл>
   ```
   (либо `--auto-glossary` вместо `--glossary`; если я просил «читабельный»
   перевод, а не черновик — добавь `--polish`, детали в
   `$ROOT\КОНФИГУРАЦИИ.md`). GPU: перед каждым извлечением
   оркестратор сам выгружает LLM (`lms unload --all`) — модель, оставшаяся в
   памяти от предыдущей книги, иначе загоняет MinerU в thrashing до зависания
   системы. Если запускаешь стадии вручную — выгружай модель сам (Eject в
   LM Studio) перед извлечением; после извлечения JIT вернёт её автоматически.
3. Живой процесс не убивай. Упал — прочитай хвост лога, устрани причину,
   перезапусти ту же команду.
4. Не собрался PDF → `_translated\<книга>_ru\build\main.log`; типовая причина —
   неэкранированный спецсимвол в прозе (`% & _ # $ { }` → `\% \& \_ \# \$ \{ \}`).
   Правь `build\body.tex`, пересобирай `bash D:/0FREETRANSLATE/scripts/build.sh <...>/build/`.
   **Максимум две попытки на книгу**, дальше — пропустить и зафиксировать в отчёте.

## Режим Б — конвейер по частям, вставка в существующий каркас

Если каркас типовой (главы подключены `\input`, в заглушках `\origpages{a--b}`
и маркеры вида «>>> … раздела N.M … <<<») — всё делает отдельный оркестратор:
```powershell
& $PY $ROOT\skeleton\translate_into_skeleton.py . --offset <N> --extract math
```
(`--offset`: pdf_страница = книжная + N, ищи в заметках проекта; сначала
`--dry-run` и сверь план; повторный запуск возобновляет — заполненные разделы
не трогаются; разделы без пары ищи в `_skeleton_work/<глава>/leftover.md`).
Подробности — `$ROOT\skeleton\README.md`.

Каркас нетиповой или нужна отладка — ручные стадии. Определи родной движок
сборки по `main.tex`/преамбуле (LuaLaTeX или XeLaTeX) — собирать только им.
По каждой главе войди на **первой недостающей стадии** (готовые артефакты
не переделывать):

1. **Нарезка страниц главы** из исходного PDF (диапазоны и смещение
   pdf ↔ книжная страница — из заглушек `\origpages` и заметок проекта);
   pymupdf из venv.
2. **Извлечение**: `mineru -p <глава.pdf> -o <out>` (math) или marker.
   Если модель осталась в VRAM от перевода предыдущей главы и преflight/скорость
   намекают на тесноту — `MINERU_VIRTUAL_VRAM_SIZE` / Eject в LM Studio.
3. **Санация**: `& $PY $ROOT\scripts\clean_markdown.py <in.md> <out.clean.md>`.
4. **Маска**: `mask_math.py mask <clean.md> <masked.md> <map.json>`.
5. **Перевод**: `translate.py <masked.md> <ru.masked.md> --mode hymt --model hy-mt2-7b
   --host http://localhost:1234 --glossary <slim> --parallel 3` (возобновляемый).
6. **Размаскирование**: `mask_math.py unmask …` — в логе строго `unresolved: 0`.
7. **Вставка в каркас**: `pandoc <ru.md> -t latex --top-level-division=section`,
   тела секций разложить под маркеры «>>> … <<<» соответствующих разделов
   (родные номера в заголовках извлечения указывают, что куда). Заголовки
   секций из фрагмента отбрасывать — в заглушках они уже переведены.
   После заполнения главы снять `\pending`.
8. **Рисунки**: кропы извлечения → `trim_images.py` → каталог рисунков проекта,
   включение — механизмом каркаса. Перерисовка в вектор — вне этой задачи;
   какие рисунки того заслуживают, отметь в отчёте.
9. **Сборка** родным движком, ошибки по логу; **максимум две попытки на главу**,
   дальше — пропустить, зафиксировать, идти к следующей.

Если в проекте есть файл прогресса — обновляй в нём статус глав по мере готовности.

## Приёмка и отчёт

- Итоговый PDF существует и открывается; каркасная книга собирается целиком.
- У каждой книги/главы `unresolved: 0` (формулы не потеряны).
- Проверь `plaques_report.md` в рабочей папке: если конвейер нашёл кандидатов
  в текстовые плашки (затенённые определения, уехавшие картинками), выполни
  vision-проход по готовому промпту `plaques_vision_prompt.md` (лежит рядом),
  затем `rescue_plaques.py patch` и пересборка. Иначе в PDF останутся
  английские рамки-картинки.
- Замечания верификаторов (в режиме А `audit_selfcheck`/`layout_report`
  запускаются сами) — вынести в отчёт, чинить только то, что ломает сборку.
- Итоговый отчёт: книга/глава — статус (готова / пропущена / ошибка) — путь
  к результату — ключевые замечания; для упавших — причина и что попробовать вручную.
