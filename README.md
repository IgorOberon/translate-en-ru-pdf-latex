# translate-pdf-latex

**Перевод книг локальной моделью — извлечение, перевод и вёрстка LaTeX/PDF.**

Local-first book translation with resumable jobs, protected formulas, and a portable AI-agent skill. The translation engine accepts source/target languages supported by the selected model; packaged end-to-end routes currently focus on Russian output.

Ранее проект назывался `translate-en-ru-pdf-latex`. Новое имя не ограничивает
назначение одной языковой парой, но **не означает, что любой язык уже поддержан
всеми стадиями**. См. раздел о языках ниже.

Главная идея: **книгу переводит локальная модель, а недорогой ИИ-агент только управляет конвейером**. Можно работать через OpenCode, другой агент с доступом к терминалу или вообще без агента — обычными командами.

По умолчанию: **Hy-MT2 локально, без облака, обязательной полировки и автоматического создания глоссария**. Существующий глоссарий можно использовать. Дорогая подписка управляющего агента для запуска не требуется.

## Как это работает

```text
PDF / документ / подготовленный проект
  → извлечение текста, формул и рисунков
  → проверка структуры и подготовка Markdown
  → маскирование формул, разметки и ссылок
  → перевод локальной Hy-MT2 с кэшем блоков
  → восстановление масок и технические проверки
  → Pandoc → LaTeX → новый PDF
```

Для PDF с математикой используется MinerU. Перед GPU-извлечением модель в LM Studio выгружается; перед переводом конвейер проверяет завершение процессов MinerU. Одновременную работу двух больших моделей на одной видеокарте допускать нельзя.

## Возможности

- Отдельная папка задания: исходные книги и готовые PDF не перезаписываются.
- Возобновление после сбоя с проверяемым кэшем; таймауты, логи и компактный статус.
- Маскирование формул, кода, ссылок и меток сносок; проверка повреждённых или потерянных масок.
- Восстановление однозначных сносок MinerU из JSON и простых прямоугольных HTML-таблиц. Неоднозначные случаи требуют проверки.
- Последовательный перевод папки книг.
- Работа с существующим LaTeX-каркасом и подготовленными OCR-проектами.
- Другие локальные OpenAI-совместимые серверы; удалённые модели — только при явной настройке.
- Один самостоятельный переносимый скилл. Дополнительная коллекция экспертных скиллов не нужна для обычного запуска.

## Языки: возможности и текущие ограничения

| Уровень | Что поддержано сейчас |
|---|---|
| Переводчик `scripts/translate.py` | `--source-lang` и `--target-lang`; языковая пара должна поддерживаться выбранной моделью |
| Простой запуск `pipeline.py`: книги и LaTeX-каркасы | EN→RU; другие пары явно отклоняются, а не игнорируются |
| Подготовленный OCR | Проверенный сценарий DE→RU; языки MT настраиваются, но сборка и часть проверок ориентированы на русский |
| Полный цикл для других языков | Нужны проверка OCR, языковой очистки, шаблона, шрифтов и приёмки на отдельном фрагменте |

Например, уже подготовленный **замаскированный** Markdown можно перевести
немецкий → английский выбранной локальной моделью:

```powershell
.\venv\Scripts\python.exe -X utf8 scripts\translate.py work\text.masked.md work\text.en.masked.md --source-lang German --target-lang English --mode generic --host http://127.0.0.1:8080 --model EXACT_SERVER_MODEL_ID
```

Это только стадия MT, не готовый универсальный PDF-маршрут. Русские шаблоны,
кириллические проверки и очистка CJK нельзя автоматически применять ко всем
языкам. Поддержка языка моделью и поддержка полного конвейера — разные вещи.

## А где остальные 26 скиллов?

**Один скилл-конвейер и коллекция из 26 экспертных скиллов — разные комплекты.**
Этот репозиторий и основной ZIP содержат `translate-pdf-latex`: всё необходимое
для обычного программного прогона, кроме внешних программ и моделей.

Коллекция из **26 дополнительных скиллов** помогает агенту в нестандартных задачах:

есть инструменты для семинаров и транскриптов. Она полезна, но не является
обязательной зависимостью и не запускается автоматически.

## Требования

Основная проверенная среда — **Windows**. Полная установка с нуля на Linux/macOS не подтверждена.

| Компонент | Для чего нужен |
|---|---|
| Python 3.10+ и `requirements.txt` | Скрипты, проверки, работа с PDF и процессами |
| [Pandoc](https://pandoc.org/installing.html) | Конвертация документов и Markdown в LaTeX |
| [MiKTeX](https://miktex.org/download) или [TeX Live](https://tug.org/texlive/) с XeLaTeX | Сборка PDF; зависимости и шрифты проверяет `doctor.py` |
| [LM Studio](https://lmstudio.ai/) и [Hy-MT2](https://github.com/Tencent-Hunyuan/Hy-MT2) | Локальный перевод через API |
| [MinerU](https://github.com/opendatalab/MinerU) | Извлечение PDF с формулами; устанавливается отдельно |

Для других типов PDF доступны отдельные извлекатели — см. [установку](УСТАНОВКА.md). Не нужно ставить все OCR-движки сразу. Размер RAM/VRAM зависит от модели, квантизации, контекста и OCR-движка: универсального минимального требования этот проект не устанавливает. Проверочный GPU-прогон выполнен на RTX 5060 Ti 16 ГБ.

В репозитории и пользовательском ZIP **нет моделей, книг, готовых переводов, venv, ключей API и кэшей**. Первая установка требует загрузки зависимостей. Для дальнейшей работы офлайн заранее скачайте веса OCR/MT и пакеты TeX.

## Быстрый старт на Windows

Распакуйте пользовательский ZIP из [Releases](https://github.com/IgorOberon/translate-pdf-latex/releases) в короткий путь, например `D:\Tools\translate-pdf-latex`, или клонируйте репозиторий. Команды ниже выполняются из его корня.

1. Установите Python, Pandoc, TeX и LM Studio по [инструкции](УСТАНОВКА.md).
2. В LM Studio скачайте Hy-MT2, включите сервер на `127.0.0.1:1234`, JIT-загрузку и CLI `lms`. Не открывайте API в интернет.
3. Установите базовые Python-зависимости:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

Установщик не ставит автоматически LM Studio, модели, CUDA, Pandoc, TeX и OCR. Если проверка сообщает о недостающем компоненте — установите его и повторите проверку.

### Первый тест — без OCR

```powershell
.\venv\Scripts\python.exe -X utf8 tests\run_smoke.py
.\venv\Scripts\python.exe -X utf8 scripts\doctor.py --host http://127.0.0.1:1234 --model hy-mt2-7b
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py init assets\quickstart.md --out 'D:\Translations\demo-01'
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py plan 'D:\Translations\demo-01'
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py run 'D:\Translations\demo-01'
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py status 'D:\Translations\demo-01'
```

`demo-01` должна быть новой папкой. Точный ID модели проверьте через `http://127.0.0.1:1234/v1/models`; если он другой, задайте его в настройках ниже и добавьте `--settings` к `init`.

### PDF с формулами — MinerU

Установите MinerU и его GPU-зависимости по [инструкции](УСТАНОВКА.md). Сохраните `local-model.json` в UTF-8 без BOM, подставив точный ID своей модели:

```json
{
  "host": "http://127.0.0.1:1234",
  "model": "hy-mt2-7b",
  "mode": "hymt",
  "parallel": 1,
  "extract": "math"
}
```

```powershell
.\venv\Scripts\python.exe -X utf8 scripts\doctor.py --extract math --host http://127.0.0.1:1234 --model hy-mt2-7b
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py init 'D:\Books\book.pdf' --out 'D:\Translations\book-01' --settings .\local-model.json
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py plan 'D:\Translations\book-01'
.\venv\Scripts\python.exe -X utf8 scripts\pipeline.py run 'D:\Translations\book-01'
```

Сначала испытайте 1–3 страницы с формулой, рисунком, сноской и таблицей. Вместо файла можно указать папку книг; подпапки автоматически не обходятся. Markdown/TXT/HTML передавайте отдельным файлом.

Для продолжения повторяйте **`run` того же задания**, а не `init`. Не запускайте дубль, пока старый процесс жив. `run` занимает терминал; закрытие окна не превращает его в фоновое задание.

## Готовое задание ИИ-агенту

> Прочитай SKILL.md в корне этого проекта. Проверь окружение и модель. Переведи книги из D:\Books в новую папку задания D:\Translations\batch-01 через pipeline.py init, plan, run, status. По умолчанию всё локально, без полировки и облачного fallback. Сам книгу не переводи: управляй скриптами. Не меняй исходники и готовые PDF, не запускай одновременно GPU-OCR и модель перевода. При ошибке сохрани кэш, прочитай указанный отчёт и не обходи проверки.

Для установки как скилла перенесите **всю папку**, а не один `SKILL.md`. Пути установки в поддерживающих Agent Skills клиентах описаны в [УСТАНОВКА.md](УСТАНОВКА.md). Без поддержки скиллов достаточно открыть каталог проекта агентом и поручить прочитать `SKILL.md`.

## Ограничения и безопасность

- **`done` означает технически принятый PDF, а не научно вычитанный перевод.** Ошибки OCR и смысла остаются возможными. В реальном тесте Hy-MT2 неверно перевела словесную единицу измерения — структурные проверки этого не обнаруживают.
- Проверки масок, таблиц и сносок ловят известные классы потерь, но не доказывают полноту любого скана. Сложные таблицы и неоднозначные примечания могут потребовать ручной подготовки.
- Обязательной дорогой полировки нет. Для публикации пользователь отдельно определяет объём предметной проверки.
- Посторонний GPU-сервер нельзя автоматически убивать. Согласуйте его остановку перед запуском MinerU; лимит VRAM не заменяет выгрузку модели.
- Локальный API не является сетевой песочницей. Облачный управляющий агент может передавать своему провайдеру прочитанные им тексты. Для полного офлайна нужны подготовленные зависимости и локальный агент либо прямой CLI.
- Используйте только доверенные LaTeX-каркасы и документы, которые вы вправе обрабатывать. Ключи храните в окружении, не в JSON, Git или Issues.

```powershell
.\venv\Scripts\python.exe -m pytest tests -q
.\venv\Scripts\python.exe -X utf8 tests\run_smoke.py
```
