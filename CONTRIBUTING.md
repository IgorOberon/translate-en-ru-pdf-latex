# Разработка и сообщения об ошибках

Обычный запуск: [README.md](README.md). Перед изменением конвейера прочитайте
[AGENTS.md](AGENTS.md) и [docs/INTEGRITY.md](docs/INTEGRITY.md).

## Сообщить о проблеме

Откройте Issue и укажите:

- версию/коммит, ОС, Python и выбранный маршрут;
- OCR-движок, ID модели и локальный сервер;
- команду без секретов и статус задания;
- ожидаемое и фактическое поведение;
- короткий очищенный фрагмент лога и минимальный пример, который можно публиковать.

Не прикладывайте книгу целиком, API-ключи, приватные URL или пользовательские пути.
Для уязвимостей используйте правила [SECURITY.md](SECURITY.md).

## Проверки изменения

```powershell
.\venv\Scripts\python.exe -m pytest tests -q
.\venv\Scripts\python.exe -X utf8 tests\run_smoke.py
```

Внешние Pandoc/TeX нужны для интеграций. Обычные unit/smoke-тесты не заменяют
реальный OCR/MT-прогон. GPU-тесты запускайте только явно, в новой папке,
на синтетическом или разрешённом минимальном PDF. Не используйте готовую
книгу как изменяемую тестовую фикстуру. Не запускайте MinerU одновременно
с резидентной моделью перевода.

К каждой исправленной потере содержимого добавляйте регрессионный тест.
Не ослабляйте валидатор ради зелёного результата, не удаляйте формулы/сноски
и не исправляйте хэши отчётов задним числом. Меняйте первопричину и собирайте
новый кандидат. Платные API и полировка остаются явными опциями.

Новый скрипт/документ должен попасть в явный список `scripts/make_package.py`.
Пакуйте через `--profile user --out NEW_DIRECTORY`, проверяйте манифест
и пробуйте установку из новой распаковки. Не публикуйте всю рабочую папку.
