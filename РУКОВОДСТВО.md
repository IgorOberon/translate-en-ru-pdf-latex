# Локальный переводчик книг (EN → RU): руководство пользователя

Простой режим: [docs/LOCAL_AGENT.md](docs/LOCAL_AGENT.md).
`pipeline.py init INPUT --out NEW_JOB`, затем `run NEW_JOB`; `status NEW_JOB`
покажет результат/ошибку. Всё локально, без обязательной полировки и без LLM
для управления стадиями. Ручные команды ниже — расширенный режим.

Обновление 11.10.2026: правила кэша, отчётов и выпуска изменились.
Перед возобновлением читайте [Проверяемый перевод и выпуск](docs/INTEGRITY.md).
Проверки подтверждают технические инварианты, а не литературную/научную точность.
Неполный перевод и обход приёмки теперь дают только кандидата, не заменяя итоговый PDF.
Для OCR-книг добавлены ранние проверенные правки, отделение прибавлений и
контекстные терминологические проверки: повторный пилот Luna (`docs/опыт-тома-6/05_ПРОВЕРКА_LUNA.md`, только в полной версии).
Поля `ocr_review`/`term_guards` и способы безопасного исправления описаны в контракте.

Комплект скриптов, который берёт книгу на английском (PDF, EPUB, DOCX и другие
форматы), переводит её на русский **локальной** нейросетью и собирает готовый
русский PDF с книжной вёрсткой через LaTeX. Всё происходит на вашем компьютере:
бесплатно, приватно, без облачных сервисов и подписок. Формулы, код и ссылки
защищены от повреждения при переводе; имена и термины переводятся единообразно
по всей книге благодаря глоссарию; прерванная работа продолжается с места
остановки.

## 1. Как это устроено

Перевод книги — это конвейер из шести этапов. Понимать его полезно: тогда ясно,
что происходит на экране и что делать при сбое.

```
 книга.pdf / .epub / ...
        │
   [1] ИЗВЛЕЧЕНИЕ  ── PDF: Marker / MinerU / PyMuPDF;  EPUB и др.: pandoc
        │              → markdown-текст + картинки
   [1a] САНАЦИЯ     ── вырезать OCR-оглавление, хвост-указатель оригинала и
        │              колонтитулы, срезать хвосты заголовков, прибрать
        │              юникод-математику (--no-clean отключает; идемпотентно,
        │              с отчётом-счётчиками и аудит-файлами вырезанного)
   [1b] ГЛОССАРИЙ  ── (опц.) авто-поиск имён и терминов, перевод каждого 1 раз
        │
   [2] МАСКИРОВАНИЕ ── формулы, код, \ref, URL прячутся за токены ⟦M000123⟧
        │
   [3] ПЕРЕВОД      ── локальная модель переводит ТОЛЬКО прозу, по абзацам,
        │              с кэшем (возобновление) и глоссарием; ответ с битым
        │              токеном маски отбраковывается и переспрашивается
   [4] РАЗМАСКИРОВАНИЕ ─ формулы возвращаются на места байт-в-байт;
        │              повреждённые моделью токены чинятся автоматически
   [5] ВЁРСТКА      ── pandoc: markdown → LaTeX + русская преамбула;
        │              подписи «Рисунок [N]» приклеиваются к картинкам;
        │              обложка/предисловие — без номеров глав, а если
        │              заголовки несут родную нумерацию книги — LaTeX-номера
        │              разделов подавляются (нет «4.2 1 …» в оглавлении)
   [6] КОМПИЛЯЦИЯ   ── XeLaTeX «до стабилизации» → книга.ru.pdf; затем
                       самоаудит согласованности и отчёт вёрстки
```

Ключевые идеи:

**Маскирование** — главный механизм надёжности. Модель физически не видит
формулы: перед переводом каждая формула, блок кода, команда вида `\ref{...}`
и ссылка заменяются уникальным токеном `⟦M000123⟧`, а после перевода
возвращаются на место без изменений. Даже если модель ошибётся, математика
пострадать не может.

**Глоссарий** — файл строк вида `Alan Turing => Алан Тьюринг`. Он подставляется
модели при переводе каждого абзаца, поэтому имя героя на странице 5 и на
странице 500 переведено одинаково. Глоссарий можно написать руками или
сгенерировать автоматически (флаг `--auto-glossary`).

**Возобновление**. Каждый переведённый абзац сохраняется в кэш. Если работа
прервалась (свет, сбой, Ctrl+C) — запустите **ту же самую команду ещё раз**:
готовое извлечение пропустится, переведённые абзацы возьмутся из кэша, работа
продолжится с места обрыва. Это главная мантра всего комплекта.

**Повреждённые маски** — редкий, но коварный класс сбоев: модель изредка
искажает скобки токена (`⟨M001705⟩`, `‹M003223›`, `▦M009806◦` вместо
`⟦M001705⟧`), и точное размаскирование такой токен молча пропускало бы —
формула исчезала из книги. Теперь это закрыто с двух сторон: переводчик
отбраковывает ответы с битыми токенами и переспрашивает (до 3 раз), а
размаскирование дополнительно чинит уцелевшие огрызки по карте масок —
смотрите строку `repaired damaged: N, unresolved: K` в логе; `unresolved`
должен быть 0.

**Верификаторы**. После сборки автоматически запускаются два штатных отчёта:
`audit_selfcheck.py` (сквозная согласованность: номера формул и утверждений,
подписи и упоминания рисунков, нумерация разделов, гигиена PDF-текста) и
`layout_report.py` (метрики вёрстки, топ-5 переполненных строк со страницами,
пропавшие символы со списком, превью первой/средней/последней страницы).

## 3. Установка (один раз)

### 3.1. Что нужно

| Компонент | Зачем | Откуда |
|---|---|---|
| **LM Studio** + модель **Hy-MT2-7B** | движок перевода | lmstudio.ai; модель — поиск «Hy-MT2» внутри LM Studio (квант Q8_0) |
| **Python 3.10–3.13** | запуск скриптов | python.org (галочка «Add to PATH») |
| **marker-pdf** и/или **mineru** | извлечение из PDF | `pip install marker-pdf`, `pip install "mineru[core]"` |
| **Pandoc** | конвертация форматов и вёрстка | pandoc.org |
| **MiKTeX** (Windows) или **TeX Live** | компиляция PDF (XeLaTeX) | miktex.org / tug.org |
| *(опционально)* **Calibre** | входные DJVU/MOBI/AZW | calibre-ebook.com |

Железо: видеокарта NVIDIA с 8–16 ГБ видеопамяти — комфортный вариант
(перевод и извлечение идут на GPU). Без GPU работать тоже будет, но извлечение
из PDF станет очень медленным.

### 3.2. Настройка LM Studio

1. Скачайте модель **Hy-MT2-7B** (квант Q8_0).
2. Загрузите её с параметрами: **контекст 8192**, GPU Offload — максимум,
   Flash Attention — вкл.
3. В панели Sampling: temperature **0.7**, top_p **0.6**, top_k **20**,
   repeat penalty **1.05** (рекомендация авторов модели).
4. Вкладка **Developer → Start Server** — сервер на `http://localhost:1234`.
   Проверка: откройте в браузере `http://127.0.0.1:1234/v1/models` — должен
   вернуться JSON со списком; запомните `id` модели (обычно `hy-mt2-7b`).
5. Для ночных прогонов: в настройках Developer поднимите «Max idle TTL»
   (напр., 720 минут) и не закрывайте приложение (или включите фоновую
   «службу LLM»).

### 3.3. Окружение Python (Windows, PowerShell)

Рабочую папку проекта создавайте по **латинскому пути без пробелов**
(например, `D:\translate`) — кириллица и пробелы в путях регулярно ломают
сторонние инструменты.

```powershell
cd D:\translate                # сюда распакован комплект
py -3.12 -m venv venv          # изолированное окружение
.\venv\Scripts\Activate.ps1    # активировать (в приглашении появится (venv))
python -m pip install -U pip
pip install -U marker-pdf      # для обычных PDF
pip install -U "mineru[core]"  # для PDF с математикой (кавычки обязательны!)
pip install hf_xet             # ускоритель скачивания моделей (опционально)
```

Три специфично-виндовые настройки:

```powershell
# 1) кэш моделей извлекателя — на латинский путь (важно при кириллическом имени пользователя)
[Environment]::SetEnvironmentVariable("HF_HOME","D:\hfcache","User")

# 2) если инструменты качают модели с Hugging Face — включите «Режим разработчика»:
#    Параметры Windows → Для разработчиков → Режим разработчика (нужен для symlink'ов)

# 3) проверка, что PyTorch видит видеокарту (для MinerU/Marker):
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
#    если напечатало "+cpu False" — поставьте CUDA-сборку:
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128 --force-reinstall
```

**Ритуал каждой рабочей сессии** (три строки):

```powershell
cd D:\translate
.\venv\Scripts\Activate.ps1
# ... команды перевода
```

### 3.4. Шрифт (одна правка)

Преамбула по умолчанию просит шрифт CMU Serif, которого в Windows обычно нет.
Откройте `assets\preamble.tex` и замените три строки шрифтов на имеющиеся:

```latex
\setmainfont{Times New Roman}
\setsansfont{Arial}
\setmonofont{Consolas}
```

В MiKTeX Console включите Settings → «Install missing packages on-the-fly = Yes»,
чтобы первая компиляция сама докачала недостающие LaTeX-пакеты.

## 4. Быстрый старт: одна книга

```powershell
python scripts\translate_book.py "D:\books\mybook.pdf" --extract math --auto-glossary --parallel 3
```

Полезные флаги: `--parallel 3` — одновременные запросы к серверу (под слоты LM Studio);
`--review-glossary` — пауза после автогенерации глоссария (правите файл, жмёте Enter);
`--vram-limit 8` — щадящий режим MinerU, если система зависала на извлечении;
`--pages-per-chunk N` — размер части для толстых PDF (0 — отключить чанкинг).

Дальше скрипт всё делает сам; итог — `mybook_ru\mybook.ru.pdf` в текущей папке.
При запуске он сначала печатает баннер версии (если баннера нет — файл скрипта
повреждён) и проводит проверки: доступен ли сервер, установлены ли инструменты.
Любая проблема сообщается сразу и понятным текстом.

### Выбор режима `--extract` (только для PDF)

| Ваш PDF | Режим | Чем извлекается |
|---|---|---|
| Плотная математика (учебник, статья) | `math` | MinerU — лучшая точность формул |
| Обычный цифровой PDF | `auto` | Marker |
| Скан (в т.ч. с наложенным OCR-слоем) | `scan` (или `math`) | принудительное перераспознавание |
| Простой цифровой, без формул | `digital` | PyMuPDF — самый быстрый, без GPU |

Важно про сканы с OCR-слоем: обычный OCR (Tesseract) превращает формулы в кашу,
поэтому для математических сканов выбирайте `math` — MinerU смотрит на
изображение страницы и распознаёт формулы заново, игнорируя старый слой.

### Пауза на проверку глоссария (рекомендуется для первой книги)

С флагом `--auto-glossary` скрипт после извлечения строит глоссарий и печатает:

```
?? auto-glossary written: ...\work\glossary.md — reviewing it before a long run is recommended
```

— и, не останавливаясь, идёт переводить. Хотите проверить глоссарий глазами:
увидели эту строку → **Ctrl+C** → откройте `work\glossary.md`, поправьте
неудачные транслитерации, удалите лишнее → **запустите ту же команду снова**.
Извлечение и глоссарий подхватятся, перевод пойдёт дальше.

⚠ Правка глоссария сбрасывает кэш перевода (он входит в «отпечаток» каждого
абзаца). Поэтому редактируйте глоссарий ДО длинного прогона, а не посреди.

### Чеклист перед ночным прогоном

1. Сервер LM Studio запущен, модель загружена (или JIT включён).
2. Компьютеру запрещён сон (экран гасить можно).
3. Глоссарий проверен.
4. Не кликать мышкой внутрь окна консоли (см. раздел «Неполадки», QuickEdit).

Ориентир по времени для книги ~600 страниц с математикой на карте класса
RTX 5060 Ti: извлечение ~1–2 часа, перевод — несколько часов. Итого «вечером
запустил — утром читаю».

## 5. Пакетный режим: папка книг

```powershell
python scripts\translate_folder.py D:\books --extract math --auto-glossary
```

Что делает: находит в папке все поддерживаемые документы (форматы можно
смешивать), выстраивает очередь и переводит по одному. Поведение:

- **ошибка одной книги не останавливает очередь** — в конце печатается сводка
  (переведено / пропущено / с ошибкой);
- **повторный запуск той же команды**: готовые книги пропускаются, недоделанные
  продолжаются со своего кэша, упавшие пробуются заново;
- результаты — в `<папка>\_translated\`: рабочая папка каждой книги + копии
  всех готовых PDF на верхнем уровне;
- совпадающие имена (`book.pdf` и `book.epub`) автоматически разводятся
  суффиксом формата;
- полезные флаги: `-r` — включая подпапки, `--outdir D:\done` — куда складывать,
  `--glossary общий.md` — один глоссарий на всю серию (для книг одного автора
  это лучше, чем автоглоссарий каждой книге).

Очередь строго последовательная — видеокарта одна, параллелить книги смысла нет.
Случайно запущенный второй прогон ничего не сломает: все прогоны берут общий
замок на машину и честно ждут очереди (сообщение «жду замок конвейера…» —
см. §9).

## 6. Поддерживаемые форматы на входе

| Формат | Путь обработки | Что должно быть установлено |
|---|---|---|
| `.pdf` | Marker / MinerU / PyMuPDF (см. `--extract`) | marker-pdf и/или mineru |
| `.epub .fb2 .docx .odt .html .rst` | напрямую через pandoc (без OCR — качество максимально) | pandoc |
| `.txt .md` | берутся как есть | — |
| `.djvu .mobi .azw3` | конвертация в EPUB через Calibre → pandoc | Calibre (`ebook-convert`) |

Правило выбора: **PDF — через извлекатель, всё «рождённое цифровым» — напрямую**.
Если книга есть и в PDF, и в EPUB — берите EPUB.

## 7. Что где лежит

Для книги `mybook.*` создаётся папка `mybook_ru\` (в текущей директории или в
`--workdir`):

```
mybook_ru\
├── mybook.ru.pdf      ← ИТОГ
├── extract\           ← этап 1: markdown + картинки из книги
├── work\              ← кухня перевода:
│   ├── glossary.md         глоссарий (его вы редактируете)
│   ├── book.ru.md          готовый перевод в markdown (стоит сохранить!)
│   └── .tcache\            кэш абзацев = память возобновления
└── build\             ← LaTeX: body.tex, main.tex, main.log, картинки, main.pdf
```

Пока книга не готова и не вычитана — **ничего внутри не удалять** (особенно
`.tcache`). После вычитки можно оставить только итоговый PDF, `book.ru.md`
(перевод в markdown — пригодится для другой вёрстки) и `glossary.md` (золото
для следующей книги того же автора), остальное — удалить.

## 8. Продвинутое использование

**Другая модель или другой сервер.** Скрипты говорят с любым
OpenAI-совместимым сервером. Флаги: `--host http://localhost:11434` (Ollama),
`--model <id>`. Режим `--mode generic` включает подробный системный промпт
для обычных LLM (Qwen, Gemma) вместо фиксированного промпта Hy-MT2 — на этом
механизме работают облачные движки и литературная полировка (ниже).

**Литературная полировка одной командой.** Флаг `--polish` у
`translate_book.py` добавляет стадию 4b сразу после перевода: русский текст
снова маскируется, проходит через `translate.py --mode polish`,
размаскируется — и в вёрстку идёт `book.ru.polished.md`. Полировка не меняет
смысл текста, маски и глоссарий неприкосновенны. У стадии свой кэш
`work\.tcache_polish`, так что прерванная полировка возобновляется как всё
остальное. По умолчанию полирует Ollama (`http://localhost:11434`, модель
`qwen3.5:9b`); поменять — `--polish-model` и `--polish-host`. Слои полировки
П0..П3 и ручной цикл описаны в `КОНФИГУРАЦИИ.md`. `translate_folder.py`
пробрасывает `--polish` (и `--polish-model`/`--polish-host`) на всю партию.

**Облачные движки** — если нет GPU или хочется качества выше машинного
перевода. `translate.py --mode generic --host <OpenAI-совместимый эндпоинт>`
работает и с облаком: ключ кладётся в переменную окружения `LLM_API_KEY`,
поддерживаются хосты с версией в пути (например,
`https://generativelanguage.googleapis.com/v1beta/openai` для Gemini).
Железное правило конвейера при этом сохраняется: в облако уходит только
ЗАМАСКИРОВАННЫЙ текст — формулы не утекают и не портятся. `make_glossary.py`
тоже умеет облако (тот же `LLM_API_KEY`). Каталог готовых конфигураций
К1–К7 — в `КОНФИГУРАЦИИ.md`.

**Другой целевой язык.** `--target-lang German` — конвейер не привязан к
русскому (но преамбулу LaTeX под язык поправьте: polyglossia, шрифты).

**Ручной пошаговый режим.** Все шесть этапов можно запускать по отдельности —
команды перечислены в `SKILL.md` и `README`. Нужен для отладки: например,
перезапустить только компиляцию после правки `build\body.tex`.

**Работа с AI-агентом.** Папка комплекта — это готовый «скилл» открытого
стандарта Agent Skills: положите её в `.opencode/skills/` (OpenCode) или
`~/.claude/skills/` (Claude Code), и агент сам прогонит конвейер и, что ценно,
сам починит ошибки компиляции LaTeX по логу.

**Свой глоссарий без автогенерации.** Файл строк `term => перевод`, передаётся
как `--glossary path\to\glossary.md`. Держите его компактным (до ~60 строк):
маленькие модели теряют инструкции при перегрузке. Автогенератор ловит только
слова с заглавной буквы — строчные термины («gradient descent») дописывайте
руками.

**Тонкий глоссарий из большого мастера.** Мастер-глоссарий длиннее ~100 строк
размывает внимание 7B-модели — переводы терминов начинают «плыть». Выход —
не резать мастер, а кормить модель выжимкой:

```powershell
python scripts\slim_glossary.py мастер.tsv --chapter 5 --max-rules 100 --out slim.md
```

В выжимку попадают всегда-классы (имя, ловушка, конвенция, производное,
аббревиатура — по пометке в колонке note) плюс строки с пометкой «гл.N»,
всего не больше `--max-rules`. Мастер остаётся источником истины для аудита
согласованности.

**Профили вёрстки.** `--layout screen` (по умолчанию — прежнее поведение,
чтение с экрана), `--layout print` (двусторонняя печать: развороты, главы с
правой полосы, переплётное поле 8 мм), `--layout compact` (10pt, поля 1.8 см,
`\raggedbottom` — заметно меньше страниц для черновой вычитки). Профиль — это
блок переопределений в собираемом `main.tex`; сама преамбула не форкается.

**Титульный лист.** `--title "Название" --author "Автор"` — простой титул
перед оглавлением. По умолчанию титул получает имя входного файла, автор пуст.

**Умная сборка.** Компиляция гоняет XeLaTeX не фиксированное число раз, а «до
стабилизации»: после каждого прохода сверяется md5 от `main.aux`+`main.toc`;
как только они перестали меняться — сборка завершена (максимум 4 прохода,
в логе `pass N/4`).

**Санацию можно выключить**: `--no-clean` пропускает этап 1a целиком, а
отдельные правила отключаются флагами `--no-strip-toc`, `--no-attach-eq-tags`
и т.п. при ручном вызове `clean_markdown.py`.

**Плашки-картинки (vision-rescue).** MinerU иногда классифицирует затенённые
рамки-определения и постулаты как картинки: их текст не попадает в перевод, и
в готовом русском PDF такие плашки остаются английскими серыми рамками.
Конвейер сам детектирует кандидатов после извлечения и пишет два файла:
`plaques_report.md` (список подозрительных рамок) и ГОТОВЫЙ промпт
`plaques_vision_prompt.md` — в нём пути кропов, правила классификации, формат
JSON и команда патча. Восстановление: vision-агент (например, Claude) читает
кропы как картинки и выдаёт JSON `{hash, kind, title_ru, body_ru}`, после чего

```powershell
python scripts\rescue_plaques.py patch плашки.json build\глава.tex
```

вставляет рамку с переводом и снимает дублирующийся заголовок. Пере-распознавать
кропы самим MinerU нельзя — его VLM виснет часами. На реальной книге так
восстановлено 16 плашек в шести главах.

**Перевод в свой LaTeX-каркас (skeleton-оркестратор).** Для проектов, где уже
есть собственный `main.tex` и заглушки глав с маркерами
`% >>> сюда вставить … раздела N.M … <<<` и `\origpages{a--b}`, обычный
конвейер не нужен — перевод вставляется прямо в ваш каркас:

```powershell
python skeleton\translate_into_skeleton.py D:\мой_проект --offset N [--chapters ch01,ch02] [--dry-run]
```

Перевод встаёт точно на маркеры, книга собирается РОДНЫМ движком проекта
(LuaLaTeX/XeLaTeX определяется автоматически), у каждой главы остаётся
резервная копия `chNN.tex.orig`, работа возобновляема, непарные разделы
складываются в `leftover.md`. Приёмка главы: `unresolved: 0` плюс доля
кириллицы не меньше 50% букв прозы — иначе глава бракуется явно; после сборки
автоматически запускается `layout_report` (превью в `book\preview\`).
Обычные `translate_book.py`/`to_latex.sh`/`build.sh` в таком проекте запускать
НЕЛЬЗЯ — они построят параллельную книгу рядом с вашей. Подробности и формат
маркеров — `skeleton/README.md`.

## 9. Устранение неполадок

| Симптом | Причина | Лечение |
|---|---|---|
| Запуск молчит, даже баннер не печатается | повреждён файл скрипта или отвечает «не тот» python | перекачать скрипт; `where.exe python` — первым должен быть venv |
| `Server not reachable ... 10054` | системный прокси/VPN или антивирус вклинивается в localhost | скрипты уже обходят прокси; используйте `--host http://127.0.0.1:1234`; проверьте сервер в браузере; исключение в антивирусе |
| `'mineru' not found` | не установлен / не тот venv | `pip install "mineru[core]"` в активированном venv |
| `No matching distribution found for mineru` | Python старше 3.10 (частый случай — древняя Anaconda) | создать venv на Python 3.10–3.13 и работать из него |
| `WinError 1314` (symlink) при скачивании моделей | Windows запрещает симлинки обычному пользователю | включить «Режим разработчика» (или разово запустить от администратора) |
| В логе MinerU `gpu_memory: 1 GB`, всё очень медленно | видеопамять занята другой моделью, ИЛИ стоит CPU-сборка PyTorch | LLM теперь выгружается автоматически перед каждым извлечением (`lms unload --all`); если симптом остался — проверить `torch.cuda.is_available()` и поставить CUDA-сборку (см. §3.3) |
| `Timed out waiting for result` у MinerU | у клиента MinerU жёсткий лимит ~60 мин на задачу | предотвращается автоматически: PDF крупнее 200 стр. в режиме `math` извлекается частями (`--pages-per-chunk`, 0 = отключить); при сбое — та же команда, готовые части не теряются |
| Извлечение прервалось с кодом `124` | VLM MinerU стохастически завис в генерации (наблюдались многочасовые зависания) — дерево процессов убито по таймауту (`--mineru-timeout`, по умолчанию 3600 с на чанк книги, 1800 с на главу skeleton) | перезапуск той же команды безопасен — кэш цел; зависший чанк `extract_chunked` один раз повторяет сам |
| Прогон печатает «жду замок конвейера (держит pid N…)» и стоит | это штатная очередь, не зависание: GPU один, поэтому все прогоны берут общий замок на машину (`%TEMP%\freetranslate.lock`) | просто подождать; замок погибшего прогона снимается сам через ~10 минут, вручную — удалить файл замка; `--no-lock` отключает очередь (осознанно) |
| Консоль «замерла», проценты не растут, GPU 0% | клик мышью включил режим выделения (QuickEdit) и ОСТАНОВИЛ программу | нажать Enter в окне консоли; навсегда: свойства окна → снять галочку QuickEdit |
| Диспетчер задач показывает GPU 0–2%, хотя всё работает | стандартные графики не видят CUDA | переключить график на «Cuda» или смотреть `nvidia-smi` |
| `Undefined control sequence \pandocbounded` / `\real`, затем «100 errors» | pandoc 3.x использует макросы своего шаблона | уже определены в preamble.tex комплекта; в старой сборке — добавить `\providecommand{\pandocbounded}[1]{#1}` и `\providecommand{\real}[1]{#1}` в main.tex |
| Ошибка компиляции LaTeX | чаще всего незаэкранированный спецсимвол или отсутствующий шрифт | смотреть `build\main.log`; спецсимволы `% & _ # $ { }` экранировать `\%` и т.д.; шрифт — §3.4. После правки — та же команда (долетит до компиляции за секунды) |
| `model not found` на этапе глоссария/перевода | модель выгружена, а JIT не подхватил | загрузить модель кнопкой в LM Studio и повторить ту же команду |
| Перевод остановился: `exit 3` (10 неудачных блоков подряд), или глава забракована по доле кириллицы (<50% букв прозы) | сервер перевода умер или отдаёт мусор — раньше такое молча оставляло английский текст в «принятой» главе | так и задумано (fail-fast + приёмка): поднять сервер и повторить ту же команду — кэш цел, работа продолжится с места обрыва |
| Иероглифы/китайский текст в переводе (в т.ч. внутри формул) | галлюцинации MinerU при извлечении скана — приходят из извлечения, не из перевода | чинится автоматически: санация вырезает CJK (аудит вырезанного — `<имя>.removed_cjk.md`, отключение — `--no-strip-cjk`), переводчик бракует ответы с CJK; старый кэш ревалидируется сам при чтении |
| Формулы пропали из книги / огрызки `M######` в тексте | модель повредила скобки токенов масок (`⟨M…⟩`, `‹M…›`, `▦M…◦`) | восстанавливается автоматически (v2): смотреть строку `repaired damaged: N, unresolved: K` в логе unmask; при `unresolved > 0` — найти `M######` в `work\book.ru.md` и повторить команду |
| `Missing character: There is no … in font` в логе | символы молча исчезают из PDF: юникод-математика в тексте (⟨ ⟩ ∘ и т.п.) или повреждённые маски | нормализуется санацией (правило `--normalize-unicode-math`) и ремонтом масок; остаток перечислит `layout_report.py` списком — экзотику можно добить `\newunicodechar` в преамбуле |
| `latexmk ... 'perl'` (MiKTeX) | MiKTeX ставит latexmk без Perl | скрипт сам переключается на прямой xelatex (2 прохода); Strawberry Perl — по желанию |
| Система намертво зависла при извлечении, «Общая память GPU» растёт | MinerU переполнил VRAM на плотных страницах и свопится в ОЗУ | LLM перед извлечением выгружается автоматически; если зависает и без неё — запускать с `--vram-limit 8` |
| `os error 1455: файл подкачки слишком мал`, извлечение падает, сервер LM Studio отвечает 400/500 | зомби-процессы MinerU (сервер + воркеры, по 0.6–2.6 ГБ каждый) копятся с каждым запуском и исчерпывают память | добиваются автоматически до и после каждого извлечения; вручную — завершить python-процессы MinerU в диспетчере задач и повторить ту же команду |
| В PDF рамки «[рисунок не найден]» | картинок нет/битые (страховка в преамбуле не даёт сборке умереть) | `check_images.py body.tex images` покажет чего не хватает; доизвлечь `extract_chunked.py`; экзотические JPEG лечит `reencode_images.py` |
| PowerShell показывает кракозябры вместо русского | консоль читает UTF-8 в cp1251 | файл цел; смотреть `Get-Content ... -Encoding UTF8` или редактором |
| `mineru/pandoc not found` в новом окне | venv не активирован | ритуал: `cd <папка>` -> `.\venv\Scripts\Activate.ps1` (в приглашении должно быть `(venv)`) |
| MiKTeX не ставит пакеты несмотря на «Always» | настройка задана в админ-режиме Console, а компилирует пользователь | открыть MiKTeX Console ОБЫЧНЫМ пользователем и включить Always там |

Универсальный рецепт почти любой беды: устранить причину → **повторить ту же
команду** → всё сделанное подхватится из кэша.

## 10. Честные ожидания

- **Вычитка обязательна.** Извлечение из PDF не бывает идеальным (особенно на
  сложной вёрстке и плотных формулах), а машинный перевод — не редактор.
  Выборочно сверяйте формулы с оригиналом и просматривайте текст.
- **Вёрстка — стандартная книжная LaTeX**, а не копия дизайна оригинала:
  главы, формулы, картинки с переведёнными подписями, русские переносы и
  кавычки. Двухколоночные развороты и фирменное оформление не воспроизводятся.
- **Картинки вставляются как есть** — надписи внутри рисунков остаются
  английскими (переводится подпись под рисунком).
- **Скорость**: часы на толстую книгу; конвейер рассчитан на «запустил на ночь».
- Модель Hy-MT2 распространяется по лицензии Tencent Community License —
  проверьте её условия для вашей юрисдикции и целей (для личного использования
  в большинстве стран ограничений нет; лицензия не действует в ЕС,
  Великобритании и Южной Корее).

### Известные ограничения (наблюдались на реальной книге)

- **Двойная нумерация заголовков** лечится автоматически (structure.lua):
  когда большинство подзаголовков несут родные номера, LaTeX-нумерация
  разделов подавляется. Вернуть прежнее поведение: `--heading-numbers latex`.
- **Предметный указатель оригинала** вырезается санацией автоматически
  (номера страниц исходного издания в переводе бессмысленны); вырезанное —
  в `<имя>.removed_index.md` для аудита, отключение — `--no-strip-index`.
  Настоящий русский указатель — отдельная работа (imakeidx/upmendex).
- **Списки упражнений**: OCR иногда теряет маркеры («2 Используйте…» становится
  плоским абзацем). Автоматически не чинится — не отличить от номеров
  утверждений.
- **Библиография**: OCR может склеить соседние записи; имена-заголовки
  конвейер понижает до жирных абзацев автоматически, склейки остаются.
- **Внутри формул** английские связки (`\text{and}`, `\text{where}`) не
  переводятся — модель формулы не видит (это цена гарантии их сохранности).

## 11. Шпаргалка

```powershell
# сессия
cd D:\translate && .\venv\Scripts\Activate.ps1

# одна книга (PDF с математикой)
python scripts\translate_book.py "D:\books\book.pdf" --extract math --auto-glossary

# то же + литературная полировка (стадия 4b, см. §8)
python scripts\translate_book.py "D:\books\book.pdf" --extract math --auto-glossary --polish

# одна книга (EPUB/DOCX/TXT/MD)
python scripts\translate_book.py "D:\books\book.epub" --auto-glossary

# папка целиком
python scripts\translate_folder.py D:\books --extract math --auto-glossary

# после ЛЮБОГО сбоя или Ctrl+C
<та же самая команда ещё раз>

# только построить глоссарий (для ручного ревью до перевода)
python scripts\make_glossary.py extract\book\book.md glossary.md

# приёмка комплекта после обновления скриптов (компиляция + 5 тест-наборов)
python tests\run_smoke.py
```

Приятного чтения по-русски.
