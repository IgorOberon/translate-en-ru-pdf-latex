# skeleton — оркестратор перевода в чужой LaTeX-каркас

Без ручной маршрутизации: `python scripts/pipeline.py init PROJECT --out NEW_JOB`
из корня конвейера, затем `run NEW_JOB`. Диспетчер работает с копией проекта,
не меняет исходный PDF/TeX и не включает полировку. Нужен один исходный PDF
в корне проекта; остальные настройки — [LOCAL_AGENT](../docs/LOCAL_AGENT.md).
Прямые команды ниже — расширенный режим с записью в указанный проект.

Новые правила возобновления и выпуска: [docs/INTEGRITY.md](../docs/INTEGRITY.md).
Извлечение, folio-карта и перевод главы проверяются по хэшам; legacy-извлечение
без метаданных требует явного `--force` или отдельной рабочей копии. `--force`
пересчитывает также извлечение, сохраняя прежние данные. Неполная глава не вставляется.
Сборка идёт в `.build-candidates/candidate-*`; прежний `main.pdf` заменяется только
после технической приёмки. Готовые главы при сборке не проходят повторную смысловую
вычитку. Копии входа, кэш, отчёты и `.bak` не удалять автоматически.

`translate_into_skeleton.py` — версия оркестратора для проектов, где вёрстка
уже существует: свой `main.tex`, своя преамбула (LuaLaTeX или XeLaTeX), заглушки
глав с маркерами вставки. Стадии те же, что у `scripts/translate_book.py`
(нарезка страниц → извлечение → санация → маскирование → перевод →
размаскирование), но результат раскладывается по существующим файлам глав,
и книга собирается **родным движком проекта** — никакого собственного
pandoc-документа.

## Ожидаемое устройство проекта (образец: D:\classical mechanic)

```
<project>/book/main.tex           мастер: главы подключены \input{chapters/chNN}
<project>/book/chapters/chNN.tex  заглушки: \section{…} + \origpages{a--b} +
                                  строка  % >>> сюда вставить … раздела N.M … <<<
<project>/figures/chNN/           каталоги рисунков глав
<project>/glossary.md             фид глоссария `en => ru` (подхватывается сам)
<project>/<книга>.pdf             исходник (берётся крупнейший PDF, или --source)
```

## Запуск

```powershell
$ROOT = "D:\Конвейер"          # ← куда распакован пакет конвейера
$env:PATH = "$ROOT\venv\Scripts;$env:PATH"
& "$ROOT\venv\Scripts\python.exe" "$ROOT\skeleton\translate_into_skeleton.py" `
    "D:\classical mechanic" --offset 14 --extract math --chapters ch01
```

- `--folio auto|offset|off` (по умолчанию `auto`) — как находить главу в PDF.
  `auto`: каждая глава ищется **сама** по печатным номерам страниц (folio) из
  текстового слоя, `--offset` не нужен; если он задан и расходится, печатается
  фактический (`>> ch14: фактический офсет 17 (задан 14)`). `offset`: только по
  `--offset`, но нарезка всё равно сверяется зондом folio. `off`: без
  folio-логики (книги, где номера не читаются и зонд даёт ложные срабатывания).
- `--offset N` — смещение страниц: pdf_страница = книжная + N. Запасной вход:
  нужен, только если folio не извлекаются (скан без текстового слоя).
  **Внимание**: единый офсет на книгу — ненадёжен, он дрейфует (см. «Проверено
  боем»); поэтому по умолчанию работает folio-локация.
- `--chapters ch01,ch03` — какие главы; по умолчанию все, где остались маркеры.
- `--dry-run` — показать план (главы, разделы, диапазоны страниц), ничего не менять.
- `--extract math|auto|scan` (math по умолчанию), `--glossary`, `--model`,
  `--host`, `--parallel`, `--vram-limit`, `--engine`, `--no-build`, `--no-intro`,
  `--force` — как в основном конвейере.
- `--mineru-timeout С` (1800 по умолчанию — главы по 20–40 стр.): VLM MinerU
  стохастически виснет в генерации; по таймауту дерево процессов убивается
  (код 124), перезапуск той же команды безопасен.
- `--no-lock` — не брать глобальный замок конвейера. По умолчанию прогон
  ждёт в очереди, если конвейер уже работает где-то на машине
  (`%TEMP%\freetranslate.lock`, снимается сам через 10 мин после гибели
  держателя).
- `--no-dup-check` — не браковать главу при повторе подзаголовков внутри
  одного раздела (для книг с законно повторяющейся структурой).

## Что он делает с каркасом

- Тело каждого раздела встаёт **на место своего маркера** (сопоставление по
  родному номеру в заголовке: `1.2`, `13.5`, `A.1`); текст главы до первого
  раздела — после `\pending`/`\chapter`. Перед первой правкой файла главы
  создаётся резервная копия `chNN.tex.orig`.
- Маркер исчез — раздел считается готовым и не трогается (возобновляемость).
  `\pending` снимается, когда в главе не осталось маркеров.
- Разделы перевода, не нашедшие маркера, уходят в `_skeleton_work/<глава>/leftover.md`
  (не теряются и не приклеиваются молча к соседям). Типичная причина — склеенные
  при извлечении заголовки: у Тейлора так остались без пары 9.10, 10.9 и A.2
  (3 раздела из 135); их тела вставляются из leftover.md вручную.
- Картинки извлечения копируются в `figures/<глава>/` с префиксом главы, пути
  переписываются; обёртки pandoc (`\pandocbounded`, `\tightlist`, `alt=`)
  заменяются чистым graphicx с ограничением ширины по `\linewidth`.
- Рабочие артефакты — в `<project>/_skeleton_work/<глава>/` (нарезка, извлечение,
  кэш перевода `.tcache`); повторный запуск продолжает с места остановки.
- Перед каждым извлечением LLM принудительно выгружается (`lms unload --all`):
  модель, оставшаяся в памяти после перевода предыдущей главы, загоняет MinerU
  в thrashing вплоть до зависания системы; JIT вернёт её при первом запросе
  перевода.
- До и после каждого извлечения добиваются зомби MinerU (`reap_mineru()`):
  каждый запуск mineru оставляет жить свой fast_api-сервер и
  multiprocessing-воркеры (0.6–2.6 ГБ RSS каждый); за очередь глав они
  исчерпывают commit-память Windows — «os error 1455», извлечение падает,
  LM Studio отвечает 400/500.
- Приёмка: `unresolved: 0` при размаскировании обязателен, плюс проверка доли
  кириллицы — <50% букв прозы кириллицей → глава бракуется явно (мёртвый
  сервер перевода иначе молча оставляет английские блоки в формально «зелёной»
  главе); в конце — сборка и сводный отчёт по главам.
- Положение главы сверяется с книжными страницами: нарезанный `pages.pdf`
  зондируется по folio (в т.ч. кэшированный от прошлого прогона с неверным
  офсетом), несовпадение — брак.
- Неполный перевод главы (код 4 у `translate.py`) — один авторетрай сам
  (провальные блоки не кэшируются, повторяются только они), затем брак с
  указанием `kept_source` из `chapter.ru.masked.md.report.json`.
- Глава длиннее 64 книжных страниц — предупреждение: извлечение пойдёт
  несколькими окнами MinerU, на стыке возможен дубль (см. ниже).
- После успешной сборки автоматически запускается `layout_report.py`:
  метрики вёрстки, топ overfull-строк со страницами, пропавшие глифы,
  превью страниц — в `book\preview\`. Отчёт мягкий: его замечания не валят
  прогон, но входят в приёмку.

## Проверено боем (полный Тейлор, 615 стр.)

Дополнение для новых запусков `--extract math`: перед MT выполняется общий
`prepare_mineru.py`. Сноски из `_content_list.json` возвращаются рядом с абзацем
ссылки, до разрезания главы на разделы; простые HTML-таблицы становятся Markdown.
Неоднозначные сноски/сложные таблицы останавливают главу с `.prepare.json`.
После Pandoc проверяется наличие сносок и таблиц в TeX. Это не заменяет проверку
совместимости табличных пакетов с чужой преамбулой. Готовые главы не переписываются
автоматически: новый прогон делайте в отдельном проекте.

- **Офсет страниц дрейфует по книге** — главный урок. Прогон Тейлора шёл с
  единым `--offset 14`, а истинное смещение росло по частям книги (15 → 17 →
  19: между частями вставлены нумерованные, но не считаемые страницы-
  разделители). Нарезка каждой главы обрывалась на 1–5 страниц раньше конца,
  и это молча срезало раздел «Основные определения главы» — во ВСЕЙ книге.
  Приёмка не спасала: `unresolved: 0` и доля кириллицы оценивают то, что
  извлекли, а не то, всё ли извлекли. Отсюда `--folio auto` по умолчанию:
  глава ищется по печатным номерам, а не по вере в один офсет.
- **Дубли на стыке окон MinerU**: гибридный бэкенд обрабатывает документ
  окнами по 64 страницы; ch15 (71 стр.) — единственная глава с двумя окнами
  и единственная с дублем: раздел 15.2 распознан дважды и попал в книгу двумя
  разными вариантами перевода. Копии не побайтные (второе распознавание
  независимо: `S` против `$\mathcal{S}$`), но после снятия математики проза
  совпадает буква в букву — на этом и построено правило `strip-dup-runs`
  санации. Страховка на неточный дубль (после перевода) — проверка повторов
  подзаголовков внутри раздела.

- TeX-артефакты извлечения, валившие сборку после вставки (кратные `\tag` у
  одной формулы, голый `&` внутри `\tag`, литеральные `\$...\$` вокруг формул,
  юникод-глифы ★ ⋅ 𝛺 → тофу), теперь чинит санация `clean_markdown` ДО
  перевода (repair-math + расширенный normalize-unicode-math).
- Но преамбула чужая: при `unicode-math`, не дающем легаси-имён,
  `\square`/`\Box` дают «Undefined control sequence», а `\providecommand{\Box}`
  НЕ срабатывает (ядро LaTeX уже определяет `\Box` заглушкой-ошибкой).
  Лечение: `\providecommand{\square}{\mathord{^^^^25a1}}` в преамбуле +
  замена `\Box`→`\square` в теле.
- Ручные правки `chapters/*.tex` недолговечны: перегенерация главы с `--force`
  их стирает. Долговечные правки вносить в markdown главы или в правило санации.
- Затенённые плашки-определения (Definition/Postulate) MinerU выдаёт картинками —
  их текст не переводится. Оркестратор их ДЕТЕКТИРУЕТ (`plaques_report.md` +
  готовый промпт `plaques_vision_prompt.md` в рабочей папке главы);
  восстановление — vision-проходом агента с последующим
  `rescue_plaques.py patch` (см. АГЕНТ.md → «Плашки-определения»). У Тейлора так
  восстановлено 16 плашек в 6 главах (постулаты СТО, определения инвариантной
  массы, релятивистской энергии и др.).

## Чего он не делает

- Не перерисовывает рисунки в вектор (кропы как есть; кандидатов на перерисовку
  смотреть глазами) и не переводит надписи внутри растров.
- Маркеры без номера раздела («сводка определений главы») не заполняет —
  они остаются на ручную работу и попадают в отчёт.
- Не полирует стиль: это дословный MT-перевод; литературная правка — отдельным
  проходом после.
