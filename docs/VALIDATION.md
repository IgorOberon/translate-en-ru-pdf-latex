# Проверки публичных версий — 12 октября 2026

## Установка именно из GitHub Releases (beta.1 → beta.2)

ZIP beta.1 заново скачан по публичной ссылке GitHub Releases в новую папку.
SHA-256 совпал с опубликованным файлом; `verify_package.py` подтвердил 115 файлов.
По опубликованной инструкции выполнен `install.ps1`: создан новый venv Python
3.12.10, без system-site-packages, с отключёнными пользовательскими пакетами
и убранными из PATH каталогами рабочего конвейера. Пакеты поставлены через pip
из PyPI (часть дистрибутивов взята из обычного локального кэша pip).

Все smoke-наборы прошли. На этой машине LM Studio :1234 был выключен, что доктор
правильно отметил ошибкой; после выбора имеющегося сервера :8080 и его точного ID
обязательные проверки прошли. Отсутствие необязательных OCR-пакетов осталось
предупреждением. Установку Python, Pandoc, TeX, GPU-драйверов, OCR и весов с нуля
этот опыт **не** подтверждает: это чистый venv на существующей Windows, не новая VM.

Вариант из инструкции для общей модели: `assets/quickstart.md` → локальная
`Qwen3.8-27B Local`, `generic`, один запрос → Pandoc/XeLaTeX → 3-страничный PDF.
Все 8 переводимых блоков приняты, все 3 маски восстановлены точно, unresolved=0.
Статус `done`, приёмка `technical_only`, полировка выключена. Просмотрены все
3 страницы: формула F=ma, число 2, сноска и разделы присутствуют.
Повторный `run` не изменил PDF и не создал новых логов стадий.

Готовые книги не использовались. Qwen не останавливался; MinerU/Hy-MT2 и другие
большие модели не загружались. Это новая проверка установки и Markdown→PDF,
**не** повтор полного OCR→Hy-MT2 прогона, описанного ниже.

Найдена ошибка: после `sync_skill.py` пользовательский пакет терял `profile: user`.
Повторный `make_package.py` считал его полной разработческой копией и требовал
отсутствующий `docs/ARTICLE_IDEAS.md`. В beta.2 сохраняются профиль и имя пакета,
старый манифест тоже резервируется. Реальный sync→repack теперь проходит,
добавлен регрессионный тест: **144 pytest-теста и 19 подтестов прошли**.

Beta.2 также переименовывает проект/скилл/ZIP в `translate-pdf-latex`, уточняет
языковые ограничения и добавляет каталог 26 **отдельных** экспертных скиллов.
Это не добавление универсального многоязычного PDF-режима и не публикация файлов
всей дополнительной коллекции.

## Реальный локальный цикл

Отдельный синтетический PDF, не фрагмент книги: 2 страницы, 3 формулы,
2 сноски, рисунок, таблица и переходы разделов. Новые задания без копирования
OCR/MT-кэша. Код запускался из распакованного пользовательского архива.

Среда: Windows, RTX 5060 Ti 16 ГБ, MinerU 3.4.2, PyTorch 2.11.0+cu128,
Hy-MT2-7B Q8_0 в LM Studio. CUDA-окружение и веса уже были установлены.
Это **не** доказательство полной установки с нуля на чистой Windows.

Финальный полный цикл: **169,81 с**, 19 реальных MT-запросов, 2053 входных
и 962 выходных токена. Результат: 5 страниц с титулом и оглавлением;
3 формулы, обе сноски, 1 таблица и 1 рисунок сохранены. Все страницы
отрендерены и просмотрены; переполнений полей, пропавших символов и ошибок
в финальном TeX-логе нет. Техническая приёмка пройдена.

MinerU завершён до каждого MT-запроса, одновременной работы OCR и MT
в мониторинге не зарегистрировано. Пики общей занятой VRAM по выборкам:
4426 MiB на OCR и 9822 MiB на MT. Не трактуйте их как универсальные требования.

## Что исправлено по результатам

1. Восстановление сносок, оставшихся только в JSON MinerU.
2. Преобразование простых HTML-таблиц и проверка структуры после перевода.
3. Защита идентификаторов сносок масками.
4. Двойные номера разделов короткого документа.
5. Распознавание подписи рисунка без квадратных скобок и выход за поле.
6. Более точное отслеживание процессов и проверяемая выгрузка LM Studio.

Архивная версия до публичного оформления прошла **143 pytest-теста и
19 подтестов**, полный smoke-набор и проверку структуры скилла.

## Что проверка не доказывает

- В переводе первой сноски Hy-MT2 исказила словесную единицу силы
  «kilogram metre per second squared». Исходный OCR был правильным.
  Технический валидатор не является проверкой физических утверждений.
- Заголовок Quantity переведён неточно; различие speed/velocity также требует
  предметного контроля. PDF не исправлялся вручную для демонстрации качества.
- OCR объединил заголовок и подзаголовок в длинное название главы.
- Сложные таблицы, неоднозначные ссылки, другие сканы и длинные очереди могут
  требовать дополнительной проверки. Linux/macOS целиком не проверены.

По умолчанию выпуск остаётся `technical_only`, без обязательной полировки.
Для редакционной публикации нужна отдельно выбранная предметная проверка.
Готовые книги и личные материалы в тесте не использовались и в репозитории
не распространяются.
